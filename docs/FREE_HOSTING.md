# Hosting: Vercel + Supabase (free plans)

Everything runs on **Supabase** (Postgres database, Auth, Realtime, Storage) and the
Next.js site on **Vercel** (Hobby, region `bom1` Mumbai). Supabase project region: Mumbai
(`ap-south-1`). There is no Firebase anywhere.

## How it fits together

| Piece | Where |
|---|---|
| Data | Postgres tables, one per collection (`id`, `data jsonb`) — `supabase/migrations/0001_init.sql` |
| Security | RLS **on** for every table with **no browser policies**. Browsers read/write only through the server: `POST /api/db` (rules in `functions/src/rules.ts`, a port of the old firestore.rules) and `POST /api/fn/<name>` (guard → rate limit → Zod → audit) |
| Votes | Append-only in the database too (trigger blocks delete and any change to voter/position/nominee/time) |
| Counting | `countMyVote` right after the browser writes; `runTick` sweeps anything missed. Idempotent via `counted` |
| Live counts | `rt` table (tallies, wall, election) → Supabase Realtime. Rebuilt from the tallies at most every 8 s (`functions/src/lib/live.ts`) to stay inside the free 2M messages/month |
| "Something changed" | `_changes` table pings (no data; per-student keys are HMACs) → the browser re-reads through `/api/db` |
| Sign-in | Supabase Auth: Google, or an email link generated by Supabase and sent through Brevo (`callables/login.ts`) |
| 2-step | Our own TOTP (encrypted secrets + backup codes). Proof is bound to the Supabase session (`_mfa_sessions`) |
| Uploads | Supabase Storage bucket `media` (public read), one-time signed upload URLs from `/api/media/upload-url` |

## One-time Supabase dashboard settings (done by a human)

1. **Authentication → URL Configuration**
   - Site URL: the live site, e.g. `https://electionclone.vercel.app`
   - Redirect URLs: `https://electionclone.vercel.app/auth/callback`, `http://localhost:3100/auth/callback`
2. **Authentication → Sign In / Providers → Google**: turn on, paste the Google OAuth client ID + secret
   (Google Cloud → APIs & Services → Credentials → OAuth client, type "Web"; authorised redirect URI =
   the callback URL Supabase shows). Until this is done, use the email sign-in link.
3. **Authentication → Sign In / Providers**: keep **Email** on and keep "Allow new users to sign up"
   on (first-time Google sign-in creates the user). A signed-in account that isn't on the sheet
   or in `admins` can read nothing — the server checks every request.

## Commands

```bash
npm run db:apply      # create/upgrade tables (idempotent)
npm run ops:verify    # read-only health check
npm run ops:sync      # rebuild live display + count any missed vote
```

## Vercel environment variables

Paste `.env.vercel` (private file) into Vercel → Settings → Environment Variables. On Vercel use
the **transaction pooler** (port 6543) for `SUPABASE_DB_URL`. Then open `/api/health`.

## Free-plan limits to watch

- Realtime: 200 concurrent connections. Beyond that, browsers fall back to a 30-second refresh.
- Realtime messages: 2M/month (live counts are throttled for this).
- Database 500 MB, Storage 1 GB, egress 5 GB — far above what this election needs.
